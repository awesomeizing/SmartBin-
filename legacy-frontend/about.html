SmartBin+: An IoT Based Intelligent Waste Monitoring and Route Optimization System

Submitted in partial fulfillment of the requirements for the award of the degree of Bachelor of Engineering in Computer Science and Engineering, Visvesvaraya Technological University, Belagavi. Academic Year 2025–2026.

// abstract

The problem, and the proposal

Rapid urbanization and population growth have intensified the challenge of municipal solid waste management in smart cities worldwide, rendering traditional fixed-schedule collection methods grossly inadequate. Overflowing bins in high-footfall zones, unnecessary vehicular trips to partially filled bins, escalating operational costs, and deteriorating public hygiene collectively underscore the urgent need for a data-driven, intelligent waste management paradigm.

This project proposes SmartBin+, an IoT-based intelligent waste monitoring and route optimization system designed to transform conventional waste collection into an automated, real-time, and efficiency-maximizing operation. The system employs an ultrasonic sensor (HC-SR04) mounted inside each dustbin to continuously measure the fill level by computing the distance between the sensor and the waste surface. The processed distance data is converted into fill-level percentage and transmitted wirelessly via Wi-Fi to an IoT cloud platform (Firebase Realtime Database) using an ESP32 microcontroller.

A web dashboard provides municipal authorities with live bin-status visualization, while an automated alert notification is dispatched when any bin surpasses a predefined threshold of 80–90% capacity. The modular, three-layer architecture comprising the sensor layer, communication and cloud layer, and application layer ensures scalability, maintainability, and adaptability to diverse urban deployments.

SmartBin+ delivers a cost-effective, energy-aware, and highly automated solution that significantly reduces manual inspections, optimizes waste collection routing, prevents overflow incidents, and contributes meaningfully to the realization of sustainable smart-city infrastructure aligned with United Nations Sustainable Development Goal 11.

“Municipal waste collection systems across most urban centers continue to operate on rigid, time-based schedules that bear no relationship to the actual fill state of individual bins. This fundamental disconnect between operational planning and ground reality produces a cascade of inefficiencies: bins in commercial districts overflow and create public health hazards before scheduled collection visits, while bins in low-traffic residential zones receive unnecessary collections when barely 20% full.”

// system design

Three layers, independently scalable

SmartBin+ is architected as a modular, three-layer, event-driven IoT system that decouples sensing, communication, and presentation concerns into independently operable and scalable subsystems.

LAYER 01
Sensor Layer

ESP32 microcontrollers and HC-SR04 ultrasonic sensors deployed on individual dustbins. Responsible for physical-world data acquisition: distance measurement, outlier rejection, median filtering, fill-level computation and local status indication via OLED, LED and buzzer.

LAYER 02
Communication & Cloud Layer

Manages Wi-Fi transmission over HTTPS, Firebase Realtime Database storage, and threshold-based alert logic. Includes retry with exponential back-off, authenticated writes, and rule-enforced access control.

LAYER 03
Application Layer

Delivers a live monitoring dashboard to authorized users: bin status, geographic mapping, alerting, route optimisation, analytics and the complete event audit trail.

Each layer communicates with adjacent layers through well-defined interfaces, enabling components to be upgraded or replaced without cascading impact on the rest of the system. The design prioritizes real-time data freshness, low-latency alerting, fault-tolerant transmission with retry logic, and a responsive user interface accessible from any web-enabled device.

The modular, layered design ensures the system can be horizontally scaled: adding new bin units requires only hardware replication and cloud registration, with zero modifications to the core software architecture.

Implementation issues resolved

Sensor noise and echo artifacts. The HC-SR04 occasionally produced spurious readings when waste material was positioned at oblique angles to the sensor beam. A five-sample rolling median filter was implemented to suppress transient outliers without introducing perceptible latency.

Wi-Fi reconnection handling. Intermittent disconnections caused data gaps in the Firebase timeline. An automatic reconnection handler with exponential back-off — initial retry 1 s, maximum 30 s — was added to ensure resilient cloud connectivity.

Power supply stability. Early testing with a direct USB 5 V supply revealed voltage sag during ESP32 Wi-Fi radio bursts, causing sporadic microcontroller resets. Replacing the supply with the LM2596 regulated module and adding 100 µF and 10 µF bypass capacitors at the ESP32 power pins eliminated the issue.

Memory optimization. The ESP32's 520 KB SRAM required careful JSON object sizing to avoid heap fragmentation over long uptime periods. Static buffer allocation using StaticJsonDocument<256> replaced dynamic allocation, reducing heap churn.

// honest accounting

What this system does not do

A project that names its own limits is easier to defend than one that does not. These are stated plainly here and repeated in the interface wherever they matter.

Four bins, not a city

This is a validated prototype on a controlled testbed. Every bin in the interface declares whether its data comes from a physical device, the Simulation Engine, or hardware not yet deployed. Simulated readings are visibly badged and cannot pass as live telemetry.

No GPS on the hardware

Bin coordinates are administrator-assigned registration metadata entered from a site survey, not device-reported positions. The map, tiles and geography are entirely real — only the coordinates are configured rather than sensed. GPS integration is Phase-II scope.

Straight-line routing

Route distances use haversine calculation between coordinates. Real road distance will be higher, typically by 20–40% in an urban grid. Fuel and CO₂ figures are derived from declared assumptions rather than measured, and every such figure carries its formula as a tooltip.

Statistical projection, not machine learning

Time-to-threshold forecasting uses least-squares linear regression over recorded history. It is labelled as statistical extrapolation throughout the interface. Machine-learning forecasting is Phase-II scope.

Alert evaluation runs client-side

A production deployment would evaluate threshold rules in a cloud function so alerts fire regardless of whether anyone has the dashboard open. This project has no server component, so evaluation happens in the browser.

// phase II

Where this goes next

Directions drawn from the project report's future scope and from the gaps identified in our literature survey.

From the project report

GPS-based bin location mapping

Device-reported positioning, replacing administrator-assigned coordinates and enabling deployment beyond a surveyed campus.

Machine-learning fill forecasting

Predictive fill-level modelling from historical data, replacing the current linear projection with decision trees, regression models or neural networks.

Solar-powered bin units

Off-grid sustainability, removing the battery replacement cycle that limits large-scale deployment.

Multi-sensor fusion

Toxic gas and temperature detection. The database schema already reserves these fields.

Android and iOS field application

A mobile client for collection personnel, with route navigation and in-field collection confirmation.

From the literature survey

Adaptive and dynamic routing

Real-time traffic conditions, vehicle GPS tracking and live bin status incorporated into route calculation, allowing continuous rerouting rather than a single plan computed at dispatch.

Edge computing

Extending local processing so devices function through network interruptions. The current firmware already performs threshold evaluation and filtering on-device; anomaly detection would follow.

Event-driven communication

Transmitting on meaningful change rather than on a fixed interval, reducing both bandwidth and power draw across a large fleet.

Hardened IoT security

Device authentication, intrusion detection and secure MQTT. Access control and TLS are in place; device-level attestation is not.

Smart city interoperability

Integration with urban traffic monitoring and city management platforms, so collection routing accounts for congestion and waste generation data informs urban planning.
